Performance Engineering: Lijsten, Sets en Wachtrijen

Datastructuren (B2)

Tijdsindicatie: 3 uur | Niveau: 2 | Domein: B2

Inleiding

Als software developer werkt je code vaak prima met 10 items. Maar wat als je applicatie opeens door 1 miljoen gebruikers tegelijk wordt gebruikt? In deze opdracht duik je in de wereld van tijdscomplexiteit. Je gaat niet alleen code schrijven, je gaat meten, vergelijken en beargumenteren waarom bepaalde datastructuren sneller zijn dan andere.

Deel 1: Je Gereedschapskist

Voordat je de opdracht begint, moet je weten hoe je performance meet in Python. Je krijgt hieronder de bouwstenen, maar hoe je ze in elkaar zet is aan jou.

1. Tijd meten

Om te weten hoe snel code is, gebruiken we de time module.

import time

start_tijd = time.time()

# ... Hier komt het stuk code dat je wilt meten ...
# Bijvoorbeeld: een zware berekening of een zoekactie

eind_tijd = time.time()
print(f"De actie duurde: {eind_tijd - start_tijd} seconden")

2. De Deque

Voor het tweede deel van de opdracht heb je een speciale datastructuur nodig: de deque (uitgesproken als "deck").

from collections import deque

# Een deque maak je net zo makkelijk als een lijst
mijn_wachtrij = deque([1, 2, 3, 4, 5])

# Een item toevoegen of weghalen werkt net iets anders dan bij een list
mijn_wachtrij.append(6)        # Voeg toe aan einde
item = mijn_wachtrij.popleft() # Haal weg aan het begin (links)

Deel 2: De Uitdaging (Toepassen)

Je gaat twee realistische scenario's simuleren. Voor beide scenario's schrijf je een Python-script waarin je bewijst welke methode sneller is.

Scenario A: De Spamfilter (Zoeksnelheid)

Je bouwt een filter voor een mailserver. Er is een enorme database met bekende "kwaadaardige IP-adressen". Elke keer als er een mail binnenkomt, moet je checken of het IP-adres van de afzender op die zwarte lijst staat.

Jouw taak:

  1. Genereer een verzameling van 1.000.000 willekeurige IP-adressen (gebruik integers, bv. tussen 0 en 10.000.000) die dienen als de "Blacklist".
  2. Genereer een stroom van 5.000 "nieuwe" IP-adressen die gecontroleerd moeten worden.
  3. Schrijf een script dat alle 5.000 nieuwe adressen checkt tegen de Blacklist.
  4. Doe dit op twee manieren en meet het tijdsverschil:
    • Manier 1: De Blacklist is een Python list [].
    • Manier 2: De Blacklist is een Python set {}.
Tip: Zorg dat je puur de zoekactie meet (het loopje met de check), en niet het genereren van de getallen vooraf.

Scenario B: Het Ticketsysteem (Wachtrijen)

Je beheert de backend voor een concertverkoop. 200.000 mensen staan in de digitale wachtrij. Zodra de verkoop start, worden mensen één voor één uit de wachtrij gehaald (First-In-First-Out) en verwerkt.

Jouw taak:

  1. Maak een wachtrij met 200.000 mensen (integers).
  2. Simuleer het verwerken van de eerste 2.000 mensen uit die wachtrij. Dat betekent: pak het voorste item, verwijder het uit de rij, en ga door naar de volgende.
  3. Doe dit op twee manieren en meet het tijdsverschil:
    • Manier 1: Gebruik een standaard list en de pop(0) functie.
    • Manier 2: Gebruik een deque en de popleft() functie.

Deel 3: Analyse en Reflectie (Het echte werk)

Nu je de metingen hebt, is het tijd om te verklaren wat je ziet. Beantwoord de volgende vragen uitgebreid in een tekstdocument of als commentaar in je code.

Over Scenario A (Lijst vs Set)

  1. Wat was het tijdsverschil tussen de lijst en de set? Was dit een klein verschil of een factor 10, 100 of 1000?
  2. Stel dat we de Blacklist 2x zo groot maken (2 miljoen items).
    • Wat gebeurt er naar verwachting met de zoektijd in de list? (Verdubbelt die, blijft die gelijk, of kwadrateert die?)
    • Wat gebeurt er naar verwachting met de zoektijd in de set?
  3. In vakjargon spreken we over O(n) en O(1). Welke hoort bij de lijst en welke bij de set? Leg in je eigen woorden uit wat dit betekent voor de schaalbaarheid.

Over Scenario B (Lijst vs Deque)

  1. De standaard lijst in Python is razendsnel als je pop() gebruikt (het laatste item weghalen). Waarom wordt de lijst opeens extreem traag als je pop(0) (het eerste item weghalen) gebruikt?
    Hint: Denk aan wat er met de overgebleven 199.999 items in het geheugen moet gebeuren.
  2. Waarom heeft een deque (Doubly Linked List) dit probleem niet?

Conclusie

  1. Stel je bouwt een applicatie waarbij je heel vaak data moet toevoegen, maar bijna nooit hoeft te zoeken. Zou je dan een list of een set gebruiken? Waarom?
